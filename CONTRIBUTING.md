# Contributing

Thanks for helping keep this list useful. All additions and removals happen via pull request.

## Inclusion criteria

An entry must meet **all** of these:

1. **Working project or substantive resource.** Repos must build/install and have real documentation. Articles must be first-hand, substantive writing about loop engineering — not a rehash of someone else's post.
2. **Real traction.** Genuine usage or attention: stars, forks, adoption, citations, or a recognized author. Freshly created empty repos and placeholder projects will be declined.
3. **No SEO spam.** No link farms, no thin affiliate/content-marketing pages, no newsletters that exist only to capture a keyword. If the primary purpose of a page is ranking rather than teaching, it does not belong here.
4. **On topic.** The entry must be about engineering agent loops (prompting, verifying, retrying, stopping, orchestrating agents) — not general AI tooling.

## Formatting rules

- One entry per pull request, added to the correct section.
- Format: `**[Name](url)** — One-line description ending with a period.`
- GitHub repos include a star snapshot: `` `(~N★ at listing)` `` — use the real count at the time of your PR, never invent one.
- Non-English resources get a language tag, e.g. `[zh]`.
- Every URL must resolve (HTTP 200, or a redirect ending in 200) at the time of the PR. Dead-link removal PRs are always welcome.
- Keep entries in a sensible order within their section (Runtimes & Orchestrators is sorted by stars at listing).

## Self-promotion

- Submitting your own project is fine — say so in the PR description.
- Maintainer self-links (claudeskills.info) are capped at **two** across the whole list and are always marked **(ours)**. The same spirit applies to everyone: one project per author unless each independently clears the bar.

## Removals

Entries are removed when they 404, are archived without historical value, turn into spam, or drift off topic. If you spot one, open a PR or an issue.
